# 基金會管理系統架構規劃

## 一、系統定位

本系統定位為基金會內部管理系統，不作為公開網站使用。主要使用者為基金會內部行政、主管、專案人員與系統管理者。

系統以 PHP + MySQL 為主要技術基礎，採模組化設計，方便未來逐步擴充功能，例如捐款管理、會員管理、活動報名、文件管理、財務紀錄、志工管理、報表分析等。

## 二、設計原則

1. 模組化
   每個功能以獨立模組設計，降低互相影響，方便日後新增或移除功能。

2. 權限分層
   不同角色只能使用被授權的功能，例如系統管理員、主管、行政人員、一般查詢人員。

3. 安全優先
   系統雖不對外公開，仍需具備密碼安全、登入保護、操作紀錄、CSRF 防護、SQL Injection 防護等基本安全措施。

4. 可維護
   採清楚的目錄結構、共用元件、設定檔分離、資料庫 migration 管理。

5. 可擴充
   未來若需要 API、手機版、外部表單、LINE 通知、Email 通知或雲端部署，架構需可延伸。

## 三、建議技術架構

### 後端

- PHP 8.2 或以上
- MySQL 8 或 MariaDB 10.6 以上
- Composer 管理套件
- PDO 存取資料庫
- MVC 或輕量模組化架構

### 前端

- HTML
- CSS
- JavaScript
- Bootstrap 5 或 Tailwind CSS 擇一
- 後台版面以表格、搜尋、篩選、表單為主

### 執行環境

初期可使用：

- Laragon
- XAMPP
- cPanel 主機
- Linux + Apache/Nginx + PHP-FPM + MySQL

建議開發階段使用 Laragon 或 XAMPP，正式環境使用 Linux 主機。

## 五、核心模組規劃

### 1. 登入與帳號模組 Auth

功能：

- 登入
- 登出
- 忘記密碼
- 重設密碼
- 變更密碼
- 登入失敗次數限制
- 帳號停用
- Session 逾時自動登出

安全設計：

- 密碼使用 `password_hash()` 儲存
- 密碼驗證使用 `password_verify()`
- 忘記密碼使用一次性 token
- token 儲存 hash，不儲存明文 token
- token 設定有效期限，例如 30 分鐘
- 重設密碼後立即作廢所有舊 token

## 七、安全性規劃

### 登入安全

- 密碼不可明文儲存
- Session ID 登入後重新產生
- 登入失敗過多時暫時鎖定
- Session 設定閒置逾時，例如 30 或 60 分鐘
- 帳號可停用
- 管理員可強制重設密碼

### 忘記密碼

流程：

1. 使用者輸入 Email
2. 系統產生一次性 token
3. token 明文只出現在 Email 連結
4. 資料庫只保存 token hash
5. 使用者點擊連結後驗證 token
6. 使用者設定新密碼
7. token 標記已使用
8. 舊 session 失效

內部系統若尚未設定 Email，可先提供「管理員重設密碼」功能，之後再補 Email 忘記密碼。

### 權限安全

- 每個後台頁面都要檢查登入
- 每個功能操作都要檢查權限
- 前端隱藏按鈕不能取代後端權限檢查
- 重要操作寫入 audit_logs

### 表單安全

- 所有 POST 表單加入 CSRF token
- 使用 PDO prepared statements
- 輸出 HTML 時做 escape
- 上傳檔案檢查副檔名、MIME type、檔案大小
- 禁止上傳可執行 PHP 檔

### 系統部署安全

- `.env` 不可放入版本控制
- `public` 才是網站根目錄
- `storage`、`config`、`database` 不可被瀏覽器直接存取
- 正式環境使用 HTTPS
- MySQL 帳號使用最低必要權限
- 定期備份資料庫與上傳檔案

1. 登入 / 登出

4. 角色權限
5. 儀表板
