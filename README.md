# 基金會管理系統

PHP + MySQL 的內部管理系統，目標是部署在一般租用主機 / cPanel 環境。

## 目前功能

- 登入、登出、忘記密碼與重設密碼
- 登入「記住我」：勾選後於該裝置以 selector／validator 雙段式持久權杖（資料庫僅存 sha256 雜湊、HttpOnly + SameSite=Lax cookie）記住登入，預設 30 天內（`REMEMBER_LIFETIME_DAYS` 可調）免重新登入，適合安裝為 App／PWA 長期使用；未勾選者維持既有較短閒置逾時。登出、變更密碼或帳號停用會撤銷持久權杖
- CSRF 防護、登入嘗試限制、操作紀錄
- 使用者管理、角色權限檢視與權限勾選管理
- 硬刪除權限採最高權限控管：捐款人、工作計畫、年度預算、財產、收支紀錄、講師支出、出差費用、薪資、領款收據、銀行帳戶、使用者、角色、會計科目、會計傳票、期初餘額等模組的刪除僅系統管理員可用，並附關聯保護（已入帳／有關聯資料者擋下）；刪除會計傳票會一併移除分錄並解除來源紀錄的傳票連結
- 資料建立者自助維護：捐款人、捐款、收支紀錄、零用金、講師支出、出差費用、薪資、財產、工作計畫、年度預算、領款收據、銀行帳戶等模組，資料的「建立人」本人可編輯（既有管理權限）並刪除自己建立的紀錄，且同樣受既有關聯保護（已入帳／有關聯者擋下）
- 管理者刪除權限：捐款人、薪資、工作計畫、年度預算、採購申請、收支紀錄、出差費用、零用金、領款收據等模組，具該模組「管理」權限者（不限最高權限）即可刪除紀錄，並保留既有關聯保護（已入帳／已完成驗收／有關聯者擋下）；採購申請刪除會一併移除明細與附件檔案
- 正式環境密碼重設不落地明文 token；可啟用主機 mail 寄送重設連結
- 側邊選單採手風琴式：預設全部疊起，點主群組才展開，且一次只展開一個群組（點另一個會把原先的疊回去）；手機等窄螢幕改為漢堡選單抽屜，預設收合、點按開啟，選單不再佔滿畫面、方便直接瀏覽內容
- 總儀表板
- 工作台營運提醒：待開收據、未寄送收據、採購申請、待補憑證、草稿傳票、未對帳交易與近期活動
- 捐款人管理：個人 / 組織、聯絡方式、收據抬頭、統編與封存
- 捐款紀錄：年度 / 月份查詢、捐款編號（依日期自動產生 YYYYMMDD-當日流水號）、收據狀態、寄送狀態、指定用途、一鍵建立草稿會計傳票、收據自動編號、單筆與批次開立、批次列印、收據作廢與重開、收據寄送紀錄、未寄送提醒、捐款台帳、收據列印與 CSV 匯出；一般以作廢保留軌跡，系統管理員另可硬刪除紀錄
- 採購申請：參考紙本採購單欄位，支援請購類別、請購單位、採購方式、主管部門歸類、廠商、明細、工作台式明細頁、小額採購簽核流程、驗收狀態、申請單列印與報價單 / 發票 / 合約 / 驗收 / 付款附件管理
- 董事會議管理：屆次會議建檔、出列席與討論案由（會議議程）、會後補齊決議與報告事項（會議紀錄）、確認留存，並可列印議程版、會議紀錄版與簽到表
- 陳報公文：依主管機關函文格式建立年度陳報公文（工作計畫、經費預算表、董事會議紀錄等附件清單、正本／副本受文者），附件可一鍵帶入系統既有文件，標記發文狀態並列印用印
- 年度預算編寫、檢視、編輯與核定
- 財務會計入口：會計系統、零用金、收支紀錄、講師支出費用、出差費用、薪資管理
- 零用金管理：收支紀錄、常用項目選用、常用項目新增與編輯、範例資料；系統管理員可硬刪除未入帳且未連結銀行交易的紀錄
- 零用金報表：年度 / 月份、精簡 / 詳細、項目比例、小計與總計
- 領款收據（領據）：依收支／講師費用一鍵開立、自動編號、匯款／現金別欄位、開立與作廢、列印；列表與明細頁均提供刪除（具管理權限者或建立者本人，操作前二次確認）；提供常用領款人管理（姓名、身分證字號、匯款資料），開立領據時可下拉一鍵帶入，或於表單勾選「儲存為常用領款人」自動建檔，讓經常領款者不必重複輸入
- 帳號基本資料與登入驗證碼
- 人事活動入口：工作計畫、人事管理、人事請假、活動管理、專案管理、講師管理、志工管理、行事曆管理
- 專案、活動與行事曆串接：活動可歸屬專案，並自動同步行事曆事件；活動可標記「課程週次」與「單元主題」，適合搭配學校學期的深耕教育計畫（一學期一專案）
- 專案批次產生課程週次：於專案頁一鍵依「第一次上課日期、週數（預設 16 週）、間隔週、上課時間、地點」批次建立多週上課活動，並自動歸屬專案、同步行事曆；可填入排除日期（假日／考試週）自動略過並順延補足週數，週次自既有最大週次接續編號（可分批產生）
- 連結外部日曆：可加入多個 Google 等公開日曆的 iCal（.ics）訂閱網址（亦接受 webcal://，自動轉 https），設定名稱與顏色，事件唯讀疊加顯示於行事曆月曆；支援全天／定時事件、UTC 與時區轉換、常見重複規則（RRULE）與例外日期（EXDATE）。抓取支援 gzip、內容驗證（非 iCal 會明確提示貼錯連結）與友善錯誤訊息（SSL／逾時／DNS）；行事曆頁面以已同步的快取顯示、不即時抓取以免主機對外連線逾時拖垮頁面，外部日曆更新時按「同步／全部同步」重新抓取，並顯示最後同步時間與錯誤訊息
- 活動報名、簽到名冊與成果紀錄
- 活動附件管理：照片、簽到表、核銷附件與成果文件上傳下載，並檢查副檔名與伺服器端 MIME
- 期初餘額（年度結轉）：以年度為單位設定零用金、收支簿期初餘額，可一鍵帶入前一年度期末結餘；銀行帳戶採連續結轉並於同頁參考呈現
- 銀行對帳：月份查詢、對帳狀態、對帳日與對帳表列印
- 會計報表：總帳、明細帳、試算表、收支餘絀表、資產負債表、淨值變動表、現金流量表
- 捐贈收入清冊：依捐贈單位／人彙總年度捐贈金額，格式參考主管機關範例，可列印陳報
- 收支營運表：獨立手動輸入上年度決算數／本年度決算數／本年度預算數，自動計算比較增減與比率，格式參考主管機關範例，可列印陳報（暫不連結實際收支帳務）
- 資產負債表（核備用）：獨立手動輸入本年底／上年底決算數，自動計算比較增減與比率、資產／負債／淨值合計與平衡檢查，格式參考主管機關範例，可列印陳報（暫不連結實際帳務）
- 現金流量表（核備用）：獨立手動輸入業務／投資／籌資活動現金流量、匯率變動與期初餘額，自動計算各活動淨額、現金增減數與期末餘額，格式參考主管機關範例，可列印陳報（暫不連結實際帳務）
- 淨值變動表（核備用）：矩陣式獨立手動輸入各期異動與餘額，欄為設立基金／其他基金／公積／累積賸餘／淨值其他項目，合計欄自動計算列總和，格式參考主管機關範例，可列印陳報（暫不連結實際帳務）
- 收支紀錄可一鍵建立草稿會計傳票
- 零用金可一鍵建立草稿會計傳票
- 銀行交易可一鍵建立草稿會計傳票
- 薪資紀錄可一鍵建立草稿會計傳票
- 講師支出與出差費用可一鍵建立草稿會計傳票
- 建構流程工具：環境檢查、PHP lint、發布前檢查
- 機構 LOGO：於「基金會基本資料」上傳機構 LOGO（PNG／JPG／GIF／WEBP，5MB 以內、伺服器端影像驗證），可預覽與移除；LOGO 以內嵌方式（不需另設路由）適度呈現於各項列印報表抬頭與捐贈收據抬頭，強化文件辨識
- 主要功能頁支援列印，並可透過瀏覽器列印視窗另存 PDF；列印字型全面採用標楷體（DFKai-SB／BiauKai 等，缺字時退回明體），捐贈收據並採寬鬆間距的整版 A4 排版（含外框、放大抬頭與大小章區，維持單頁）
- 列印文件簽核欄依模組屬性自動對應核章關係：人事請假為申請人／人事主管／執行長／董事長、採購經總務、財務會計與決算報表經會計、業務推動經單位主管等，已設定者（執行長、董事長、承辦）自動帶入姓名；每個核章欄位並保留獨立「蓋章」框，供實體用印
- PWA 漸進式網頁應用：提供 web manifest、應用圖示與 Service Worker，可「加入主畫面／安裝」為獨立應用，靜態資源快取加速載入，離線時顯示提示頁；為保護登入資料與 CSRF，僅快取靜態資源，頁面與寫入一律走網路
- GitHub Release 線上更新
- 資料庫更新與檢查：後台可檢視 migration 套用狀態（已套用／待套用清單），並一鍵套用尚未執行的資料庫更新（不重複執行、建議先備份）
- cPanel 安裝程序 `install.php`，完成安裝後以 `storage/installed.lock` 鎖定

## 環境需求

- PHP 8.2+
- MySQL 8 或 MariaDB 10.6+
- PHP extensions：PDO、pdo_mysql、zip
- Apache / Nginx / cPanel

## 安裝

1. 上傳系統檔案到主機網站目錄。
2. 建立 MySQL 資料庫與使用者。
3. 複製 `.env.example` 為 `.env`，並填入資料庫與網站設定。
4. 開啟：

```text
https://你的網域/install.php
```

5. 依畫面完成資料庫匯入、migration 與管理員建立。

## 線上更新設定

`.env` 主要設定：

```env
APP_VERSION=0.6.97
GITHUB_REPO=Chienfu168/jyc_sys
GITHUB_TOKEN=
UPDATE_CHANNEL=stable
MAIL_ENABLED=false
```

公開 repo 可先不填 `GITHUB_TOKEN`；私有 repo 需要 GitHub Personal Access Token，至少要能讀取 repository 與 release。

註：未設定 `GITHUB_TOKEN` 時，GitHub API 對每個對外 IP 每小時僅允許 60 次未驗證請求；在共用主機（cPanel）上與同一 IP 的其他網站共用此額度，容易出現「GitHub API 請求次數已達上限」。此時可稍後再試，或設定一組僅需 `Contents: Read-only` 權限的 `GITHUB_TOKEN`，額度提高到每小時 5000 次。系統更新頁會將「請求次數上限」與「Token 權限不足」分開提示，方便判斷。

## Release 流程

Push 到 `main` 後，GitHub Actions 會依 `.env.example` 的 `APP_VERSION` 自動建立對應 tag / release。每次要讓線上更新抓到新版本時，請先提高 `APP_VERSION`。

## 分支保護

`main` 已啟用分支保護，合併前必須通過 CI：

- `Lint & Test (PHP 8.2)`
- `Lint & Test (PHP 8.4)`

所有變更請經由 Pull Request 合併，待兩項檢查綠燈後再合併。
